# Ubuntu Touch 20.04 (Halium 10) for Redmi Note 8 (`ginkgo`)

> **Not verified on hardware.** The kernel builds, the images are produced and the
> package is assembled, but nobody has booted this yet. Treat the first boot as an
> experiment, and read the warning about A-only below before flashing.

## What this is

A recovery installer for the Xiaomi Redmi Note 8 (`ginkgo`, Snapdragon 665 /
SM6125), targeting Ubuntu Touch 20.04 on Halium 10.

| Artifact | Size |
| --- | --- |
| `boot.img` | 67,108,864 B |
| `dtbo.img` | 345,658 B |
| `system.img` | 2,735,426,008 B (sparse, 1,139,200 × 4096 B blocks, ext4) |
| installer zip | 957,619,832 B |

Kernel: **4.14.190**, CAF NICOBAR baseline, AppArmor as default LSM, binder with
`binder,hwbinder,vndbinder`, user/pid/net namespaces, seccomp filter, veth/bridge/
overlayfs for Waydroid.

## ⚠️ Read this before flashing

**ginkgo is A-only.** There is no `_a`/`_b` slot pair, so there is no second copy
of the system to fall back to. Download the stock firmware for your exact model
and region **before** you start.

The installer backs up `boot`, `dtbo` and `vbmeta` to `/sdcard` but **not**
`system` — it is far too large. Recovering a broken `system` means reflashing
stock.

`/data` must be **ext4 and unencrypted**. Stock HyperOS formats userdata as F2FS
with file-based encryption, which Halium cannot mount. Pass `--format-data` to the
installer, or re-flash with it if the first boot hangs on the splash.

## Fixed in this build

Six defects in the tree this port is based on, all upstream. The first one is the
reason this release exists rather than just being a rebuild.

**The fingerprint HAL and vendor binder services were never started.** The overlay
shipped two halium-overlay trees at once. The focal rootfs probes
`/android/system/halium`, `/android/system/ubuntu`, `/opt/halium-overlay/`,
`/usr/share/halium-overlay/` in that order and stops at the first hit — so
`/opt` won and four files under `/usr/share` were never read, including
`android.hardware.biometrics.fingerprint@2.1-service.rc` and
`vndservicemanager.rc`. Everything now lives under `/opt/halium-overlay`.

Also fixed:

- `default/ lsc-wrapper.d` had a leading space in its directory name, so
  `MIR_ANDROID_FORCE_HWC2=1` was installed where nothing reads it
- `repowerd.service` declared `[Service]` twice, so the unit could not be loaded
- `70-willow.rules` and `70-ginkgo.rules` shadowed each other; udev applies both
  in filename order, so effective permissions depended on sort order
- nine duplicate rules inside the surviving file, two of which disagreed with the
  rule that actually won
- a filename had a trailing space, invisible in `ls`
- three upstart jobs that cannot run on focal, which is systemd-only

## Build fixes

The kernel needed four patches to compile with a modern clang; all are in
`build-patches/` with reasoning in `docs/BUILD_NOTES.md`:

- `arch/arm64/Makefile` passed a **directory** to clang's `--prefix`, so the ARM32
  compat vDSO was assembled by the host aarch64 assembler and failed on
  `-mfloat-abi=soft`
- `unused-but-set-variable` was disabled only for GCC, not clang, while 229 hits
  in vendor code are compiled with `-Werror`
- 24 `techpack/audio` Kbuild files computed include paths from `$(shell pwd)`,
  which is the output directory under `O=`, so no techpack header resolved
- two drivers discarded a return value — one posted a read-done event after a
  metadata extraction failure, the other stored leftover impedance after a
  calibration read failure

## After flashing

`docs/FLASHING_GUIDE_en.md` has the steps; `docs/TROUBLESHOOTING.md` has the
failures worth knowing about. The checks that distinguish "it booted" from "it
works":

```bash
uname -a
systemctl status lxc-android-config
ls -l /dev/binder /dev/hwbinder /dev/vndbinder
ls -l /opt/halium-overlay/vendor/etc/init/vndservicemanager.rc
journalctl -u device-hacks --no-pager | tail -20
ofonoctl list
```

## Known issues

- Not verified on hardware
- `schedtune` is absent from this kernel, so the boost in `device-hacks` is a
  no-op (the write is guarded)
- `ginkgo` is in no 20.04 or 24.04 system-image channel, so OTA updates are not
  available; the system image is self-contained
